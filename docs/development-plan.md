# 开发方案

## 目标

做一个在 Apple Silicon Mac 上本地运行的 AI 有声内容工作室，包含 9 个应用：
有声书 / 广播剧、AI 播客、声音分身、会议纪要、录音后期、音效库、音乐、翻译配音、同声传译。

- 产品形态：一个 macOS App（Tauri 2 + React），不做网页版。
- 语音能力：[mlx-speech](https://github.com/appautomaton/mlx-speech)。
- 音乐：开源模型 ACE-Step 1.5（MIT）。
- 说话人区分、时间戳、人声分离：另外接入 pyannote、Qwen3-ForcedAligner、Demucs。
- LLM：本地 mlx-lm（Qwen 系列），也可切换到任意 OpenAI 兼容的云端接口。

## 定位

不和 SenseAudio 这类云端平台比功能多少，主打：

- **本地、隐私**：音频和文字不出本机。
- **长篇不按量计费**：例如 30 万字的小说按云端 TTS 3.5 元 / 万字符计算约 210 元，本地只有电费。
- **多角色和精细控制**：Drama 3 最多 16 个角色，逐句可编辑、可重做。

## 进程划分（已实现）

按运行环境分进程，而不是按模型：

| 进程 | 运行环境 | 内容 | 何时运行 |
| --- | --- | --- | --- |
| 主引擎 | 基础环境 Py3.13 | 调度、数据、编排、混音 | App 打开就常驻 |
| 语音进程 | 基础环境 Py3.13 | mlx-speech 全部模型 | 最常用，空闲一段时间后关闭 |
| LLM 进程 | 基础环境 Py3.13 | mlx-lm 自带服务 | 使用本地 LLM 时 |
| 分析进程 | 分析扩展包 Py3.13 + PyTorch | 说话人、时间戳、分离、VAD | 会议纪要、翻译配音时 |
| 音乐进程 | 音乐扩展包 Py3.12 | ACE-Step 自带服务 | 生成音乐时，用完关闭 |

## 阶段

按 1–2 名全职开发估算，仅供参考。

| 阶段 | 周期 | 内容 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- |
| 0 技术验证 | 2 周 | 每个模型在目标 Mac 上实测内存、速度、中文听感；打包验证（内置 Python + mlx-speech + PyTorch 签名公证后能在全新 Mac 上运行）；ACE-Step 能否放进同一环境 | 选型表 + 一个能安装运行的空壳 App | **下一步** |
| 1 骨架和底座 | 4 周 | Tauri 外壳、引擎守护、模型进程管理、内存调度、任务队列、音色库、剧本编辑、LLM 设置 | 装好打开后：选音色 → 生成 → 导出 | 代码已写，待 Mac 验证 |
| 2 内容生产 | 3–4 周 | 有声书、播客、音效库、音乐，质检回听 | 一章小说 → 带音效和配乐的成品 | 代码已写，待 Mac 验证 |
| 3 听写和修改 | 3 周 | 波形时间轴编辑器、说话人区分、词级时间戳；会议纪要、录音后期（找口误、单句替换）、声音分身（定时简报） | 1 小时会议录音 → 按发言人分段的纪要 | 会议纪要已写；时间轴编辑器未做 |
| 4 时间轴类 | 3–4 周 | 视频导入导出、翻译配音、同传 | 3 分钟视频 → 配音版加双语字幕 | 进程侧接口已备好，流程未做 |
| 5 发布 | 2 周 | 首次启动引导、扩展包下载、自动更新、AI 内容标识、对外接口（OpenAI 兼容 + MCP） | 可以对外分发的 .dmg | 扩展包安装已写 |

## 第 0 阶段检查清单

在一台 64GB 以上内存的 Apple Silicon Mac 上：

- [ ] `scripts/dev_setup.sh` 后 `scripts/dev.sh` 能打开 App，引擎就绪
- [ ] 每个语音模型：首次下载、加载时间、生成速度（实时倍数）、峰值内存，更新 `catalog.py` 的 `memory_gb` 和 `measured`
- [ ] 中文听感：Fish S2 Pro、dots.tts、FireRedTTS3、MOSS-TTSD、Drama 3 各读同一段 500 字文本
- [ ] 质检阈值：`qa.check_line` 的 12% 错误率阈值是否合适
- [ ] 混音：配乐压低（ducking）的力度和起止时间听感
- [ ] mlx-lm 本地 LLM 输出剧本 JSON 的成功率（`chat_json` 重试次数）
- [ ] 分析包：pyannote 在 MPS 上能否运行、速度；Qwen3-ForcedAligner 在 MPS 上能否运行
- [ ] ACE-Step：MLX 后端的内存占用和速度、中文歌词效果、能否用 Python 3.13
- [ ] 打包：`packaging/release.sh` 产出的 dmg 在一台没有开发环境的 Mac 上能运行、能录音
- [ ] 签名：扩展包下载后能被加载（库验证）

## 主要风险

| 风险 | 应对 |
| --- | --- |
| 内存不够、换模型慢 | 调度器把同一模型的任务排在一起；小模型常驻，大模型用完关闭进程 |
| 中文质量不稳定 | 第 0 阶段试听评测；质检回听自动重做 |
| 许可证 | 个人版 / 商用版开关；商用版不加载非商用模型 |
| 上游更新快 | 锁定 mlx-speech 版本；所有调用经过语音进程的适配层 |
| 长篇跑偏 | 默认逐句生成再拼接；对话模式按 400 字分段 |
| 声音克隆滥用 | 添加音色必须确认授权；导出内容加 AI 标识 |
| 内置 Python 签名公证 | 第 0 阶段最先验证 |
